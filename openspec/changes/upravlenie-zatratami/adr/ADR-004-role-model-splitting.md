# ADR-004: Модель ролей «Руководитель участка» / «Администратор» с разделением функций

## Статус
Accepted

## Контекст
Threat-model выявил угрозу **TM-03 (Elevation of Privilege, Medium): получение роли «Администратор» пользователем с ролью «Руководитель»**. Требуется разграничение доступа. Связанное требование — **NFR-SEC-003**. В spec.md FR-008 уже зафиксировано разграничение ролей.

## Решение
Две встроенные роли 1С с минимальными привилегиями:

| Функция | Руководитель участка | Администратор |
|---|---|---|
| Ввод «План затрат» | ✅ | ❌ |
| Ввод «Факт затрат» | ✅ | ❌ |
| Ввод «Выпуск продукции» | ✅ | ❌ |
| Просмотр отчёта «План-факт» | ✅ | ✅ |
| Просмотр дашборда | ✅ | ✅ |
| Изменение справочника «Статьи затрат» | ❌ | ✅ |
| Изменение справочника «Нормы расхода» | ❌ | ✅ |
| Управление пользователями | ❌ | ✅ |

Администратор не вводит факт затрат — это разделение обязанностей (segregation of duties), снижающее риск искажения данных одним лицом.

## Последствия
**Плюсы:**
- Покрывает TM-03 и NFR-SEC-003.
- Разделение обязанностей: тот, кто настраивает нормы, не вводит факт.
- Простая модель — 2 роли, легко тестировать (TC-SEC-003).

**Минусы:**
- В MVP всего 2 роли; при масштабировании потребуется больше (например, «Наблюдатель», «Аудитор»).

**Риски:**
- Неверная настройка прав → **Митигация:** тест TC-SEC-003, код-ревью прав.

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| Одна роль «Пользователь» для всех | Да | Нарушает TM-03; нет разделения обязанностей |
| Три и более ролей | Да | Избыточно для MVP; усложняет настройку |
| Роли на уровне записей (RLS) | Да | Избыточно для одного участка; 1С-механизмы сложнее |
