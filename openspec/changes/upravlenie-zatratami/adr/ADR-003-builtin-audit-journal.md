# ADR-003: Использование встроенного журнала регистрации 1С для аудита

## Статус
Accepted

## Контекст
Threat-model выявил угрозу **TM-02 (Repudiation, Medium): отрицание ввода/проведения документа**. Требуется доказательство действий пользователя. Связанное требование — **NFR-SEC-002**. В 1С есть встроенный журнал регистрации, фиксирующий события (запись, проведение, изменение) с указанием пользователя, времени и типа события.

## Решение
Использовать встроенный журнал регистрации 1С как основной механизм аудита. Включать в журнал события: запись, проведение, отмена проведения документов «План затрат», «Факт затрат», «Выпуск продукции». Собственный журнал аудита не разрабатывать.

## Последствия
**Плюсы:**
- Нулевая стоимость разработки — механизм «из коробки».
- Покрывает TM-02: фиксация пользователя, времени, действия.
- Соответствует NFR-002 (целостность) и NFR-SEC-002.

**Минусы:**
- Журнал регистрации не является «бизнес-журналом» — нет удобной выборки по документам для нетехнического пользователя (для MVP приемлемо).

**Риски:**
- Администратор может очистить журнал → **Митигация:** ограничить права на очистку; для MVP — резервная копия перед защитой.

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| Собственный регистр аудита | Да | Избыточно для MVP; дублирует встроенный механизм |
| Внешний лог-файл | Да | Не интегрирован с 1С; сложнее доказать целостность |
| Отключить аудит | Да | Нарушает NFR-SEC-002 и TM-02 |
