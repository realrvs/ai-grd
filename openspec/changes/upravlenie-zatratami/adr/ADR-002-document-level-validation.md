# ADR-002: Валидация на уровне документов 1С

## Статус
Accepted

## Контекст
Threat-model выявил угрозу **TM-01 (Tampering, High): искажение суммы факта затрат** при ручном вводе. Требуется контроль, блокирующий некорректные данные до записи в регистр. Связанное требование — **NFR-SEC-001**.

## Решение
Валидация выполняется в модуле документа на событии «Перед записью» и «Обработка проведения»:
- Сумма > 0 (для «План затрат» и «Факт затрат»).
- Обязательные поля: участок, статья, период/дата.
- Объём выпуска > 0 (для «Выпуск продукции»).
- При ошибке — документ не записывается/не проводится, выводится сообщение.

Проверка на уровне документа (а не только на уровне формы) выбрана потому, что документ может быть записан программно или через другой интерфейс; валидация в модуле документа покрывает все пути ввода.

## Последствия
**Плюсы:**
- 100% попыток с некорректной суммой блокируются (метрика NFR-SEC-001).
- Единая точка валидации — проще тестировать (TC-SEC-001).
- Покрывает TM-01 на границе TB-01.

**Минусы:**
- Дублирование проверок на форме и в модуле документа (незначительное).

**Риски:**
- Разработчик может добавить обходной путь записи → **Митигация:** код-ревью, тест TC-SEC-001.

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| Валидация только на форме | Да | Не покрывает программную запись; обходится |
| Валидация в регистре | Да | Регистр не должен содержать бизнес-логику; поздно |
| Внешняя проверка (скрипт) | Да | Не интегрируется с 1С; избыточно для MVP |
