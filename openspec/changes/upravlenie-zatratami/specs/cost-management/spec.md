## ADDED Requirements

### Requirement: Ввод плановых затрат (ID: FR-001)
Система ДОЛЖНА (SHALL) позволять вводить плановые затраты по участку и статье затрат на выбранный период.

#### Scenario: Успешный ввод плана
- **GIVEN** пользователь имеет роль «Руководитель участка» и открыл документ «План затрат»
- **WHEN** пользователь выбирает участок, период, статью и вводит положительную сумму, затем проводит документ
- **THEN** система сохраняет плановую запись в регистре «Затраты» с типом «План» и отображает документ в списке проведённых

#### Scenario: Ввод плана без обязательных полей
- **GIVEN** пользователь открыл документ «План затрат»
- **WHEN** пользователь оставляет поле «Статья затрат» или «Период» пустым и пытается провести документ
- **THEN** система блокирует проведение и выводит сообщение с перечнем незаполненных обязательных полей

### Requirement: Ввод фактических затрат (ID: FR-002)
Система ДОЛЖНА (SHALL) позволять вводить фактические затраты с привязкой к участку, статье затрат и дате.

#### Scenario: Успешный ввод факта
- **GIVEN** пользователь открыл документ «Факт затрат»
- **WHEN** пользователь вводит дату, участок, статью, количество и положительную сумму, затем проводит документ
- **THEN** система сохраняет фактическую запись в регистре «Затраты» с типом «Факт» и пересчитывает отклонение при формировании отчёта

#### Scenario: Отрицательная или нулевая сумма
- **GIVEN** пользователь вводит строку в документ «Факт затрат»
- **WHEN** пользователь указывает сумму ≤ 0 и пытается провести документ
- **THEN** система блокирует проведение и выводит сообщение «Сумма должна быть положительной»

### Requirement: Ввод выпуска продукции (ID: FR-003)
Система ДОЛЖНА (SHALL) позволять фиксировать объём выпуска продукции по участку за месяц (тонны).

#### Scenario: Успешный ввод выпуска
- **GIVEN** пользователь открыл документ «Выпуск продукции»
- **WHEN** пользователь выбирает участок, период, единицу измерения и вводит положительный объём
- **THEN** система сохраняет запись выпуска и использует её для расчёта нормативного расхода

#### Scenario: Нулевой выпуск
- **GIVEN** пользователь вводит объём выпуска
- **WHEN** пользователь указывает объём ≤ 0
- **THEN** система блокирует проведение и выводит сообщение «Объём выпуска должен быть положительным»

### Requirement: Расчёт нормативного расхода (ID: FR-004)
Система ДОЛЖНА (SHALL) рассчитывать нормативный расход как произведение нормы расхода на фактический выпуск продукции.

#### Scenario: Расчёт норматива по статье
- **GIVEN** в справочнике «Нормы расхода» задана норма для статьи «Топливо» на участке и введён выпуск за период
- **WHEN** пользователь формирует отчёт план-факт
- **THEN** система рассчитывает нормативный расход = норма × выпуск и отображает его в отчёте

#### Scenario: Отсутствие нормы для статьи
- **GIVEN** для статьи не задана норма расхода на участке
- **WHEN** пользователь формирует отчёт
- **THEN** система отображает нормативный расход как «н/д» и не блокирует формирование отчёта

### Requirement: Расчёт отклонения план-факт (ID: FR-005)
Система ДОЛЖНА (SHALL) рассчитывать отклонение как разницу между планом и фактом по каждой статье и участку, а также процент отклонения.

#### Scenario: Перерасход
- **GIVEN** план по статье «Топливо» = 100 000, факт = 115 000
- **WHEN** пользователь формирует отчёт план-факт
- **THEN** система отображает отклонение = +15 000, % = 15,0 и подсвечивает строку красным

#### Scenario: Экономия
- **GIVEN** план по статье «Материалы» = 50 000, факт = 48 000
- **WHEN** пользователь формирует отчёт план-факт
- **THEN** система отображает отклонение = −2 000, % = −4,0 и подсвечивает строку зелёным

### Requirement: Отчёт план-факт (ID: FR-006)
Система ДОЛЖНА (SHALL) формировать отчёт с колонками: статья, план, факт, норматив, отклонение от плана, % отклонения, итоговая строка.

#### Scenario: Формирование отчёта за период
- **GIVEN** пользователь открыл отчёт «План-факт по статьям»
- **WHEN** пользователь выбирает участок и период и нажимает «Сформировать»
- **THEN** система выводит таблицу по всем статьям с итоговой строкой и подсветкой отклонений

#### Scenario: Пустой период
- **GIVEN** за выбранный период нет ни плановых, ни фактических записей
- **WHEN** пользователь формирует отчёт
- **THEN** система выводит сообщение «Нет данных за выбранный период» и не формирует таблицу

### Requirement: Дашборд руководителя участка (ID: FR-007)
Система ДОЛЖНА (SHALL) отображать сводку по участку за период: общий план, общий факт, суммарное отклонение и топ-3 статьи с перерасходом.

#### Scenario: Отображение дашборда
- **GIVEN** за период есть плановые и фактические данные
- **WHEN** пользователь открывает дашборд и выбирает участок и период
- **THEN** система отображает сводные показатели и топ-3 статьи с наибольшим положительным отклонением

### Requirement: Разграничение ролей (ID: FR-008)
Система ДОЛЖНА (SHALL) разграничивать доступ: роль «Руководитель участка» — ввод плана/факта/выпуска и просмотр отчётов; роль «Администратор» — настройка справочников и норм.

#### Scenario: Попытка ввода факта администратором
- **GIVEN** пользователь вошёл с ролью «Администратор»
- **WHEN** пользователь пытается открыть документ «Факт затрат» на запись
- **THEN** система блокирует доступ и выводит сообщение о недостаточных правах

## Non-Functional Requirements

### Requirement: Производительность формирования отчёта (ID: NFR-001)
Система ДОЛЖНА (SHALL) формировать отчёт план-факт за период не более чем за 3 секунды при объёме до 10 000 записей затрат.

#### Scenario: Формирование отчёта в пределах нормы
- **GIVEN** в регистре «Затраты» до 10 000 записей за период
- **WHEN** пользователь формирует отчёт план-факт
- **THEN** отчёт формируется не более чем за 3 секунды

- **Verify Method:** замер времени выполнения отчёта на тестовом наборе данных (10 000 записей).

### Requirement: Целостность учётных данных (ID: NFR-002)
Система ДОЛЖНА (SHALL) обеспечивать атомарность проведения документов: при ошибке проведения ни одна запись регистра не сохраняется.

#### Scenario: Откат при ошибке проведения
- **GIVEN** документ «Факт затрат» содержит строку с некорректной суммой
- **WHEN** пользователь пытается провести документ
- **THEN** система не сохраняет ни одной записи регистра и выводит сообщение об ошибке

- **Verify Method:** тест с заведомо некорректной строкой; проверка отсутствия движений в регистре.

### Requirement: Аудит изменений учётных данных (ID: NFR-003)
Система ДОЛЖНА (SHALL) фиксировать в журнале регистрации 1С факт создания, изменения и проведения документов «План затрат», «Факт затрат», «Выпуск продукции».

#### Scenario: Фиксация проведения документа
- **GIVEN** пользователь провёл документ «Факт затрат»
- **WHEN** администратор открывает журнал регистрации
- **THEN** в журнале присутствует запись о проведении документа с указанием пользователя и времени

- **Verify Method:** проверка журнала регистрации 1С после проведения документа.

### Requirement: Удобство ввода данных (ID: NFR-004)
Система ДОЛЖНА (SHALL) обеспечивать ввод одной строки факта затрат не более чем за 4 действия пользователя (выбор участка, статьи, ввод суммы, проведение) при условии предзаполненных даты и участка.

#### Scenario: Ввод строки факта
- **GIVEN** пользователь открыл документ «Факт затрат» с предзаполненными датой и участком
- **WHEN** пользователь выбирает статью, вводит сумму и проводит документ
- **THEN** строка сохраняется не более чем за 4 действия

- **Verify Method:** UX-тест (замер числа действий) на демо-сценарии.

### Requirement: Совместимость с учебной версией 1С (ID: NFR-005)
Система ДОЛЖНА (SHALL) функционировать на 1С:Предприятие 8.3 (учебная версия) без использования функциональности, недоступной в учебной лицензии.

#### Scenario: Запуск на учебной версии
- **GIVEN** развёрнута учебная версия 1С:Предприятие 8.3
- **WHEN** пользователь открывает базу и выполняет демо-сценарий
- **THEN** все функции MVP доступны без ошибок лицензирования

- **Verify Method:** прогон демо-сценария на учебной версии 1С.
